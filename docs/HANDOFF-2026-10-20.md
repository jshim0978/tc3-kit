## 3. 구현 상세

### 3-1. `bin/tc3 run` (시험 스크립트 재생)
- 순서: `preflight`(FAIL 이면 즉시 종료코드 2, 아무 단계도 기록하지 않음) → `env` → `model-size` → `serve` → `verify` → `soak` → `stop` → `report` → (내부) `result`.
- 화면: 각 단계 시작에 `━━ [4/11] env — 가속기·실행환경 확인  시작 14:02:11 ━━`, 끝에 `PASS (3.2 s)`. 전체 끝에 단계별 경과 표 + `총 소요`. 기존 `capture` 출력(`$ 명령` → 출력)은 그대로.
- 실패 정책: 단계 FAIL 시 **즉시 중단**(`--keep-going` 옵션으로 계속 가능), `stop` 은 항상 수행(서버 잔존 방지), 종료코드 ≠ 0. 같은 run 디렉터리에서 `bin/tc3 run --from serve` 로 중간부터 재개 가능(재수행 이력은 report 에 남음 — 기존 메커니즘 활용).
- 옵션: `--soak-n N`, `--inline-monitor`, `--no-monitor`, `--from <step>`, `--keep-going`.
- `all` 은 유지하되 `run` 의 별칭으로 돌려도 됨(기존 테스트 깨지지 않게).

### 3-2. NPU 모니터 (`scripts/tc3_npu_monitor.py` + `lib/backend_*.sh` 의 `be_monitor_cmd`)
- 샘플링: 1 s 간격, 필드 `ts, phase, device, util_pct, mem_used_mb, mem_total_mb, power_w, temp_c`(없는 값은 빈칸). phase 는 run 이 `evidence/<run>/phase` 파일에 현재 단계명을 써 두면 모니터가 읽어 태깅(파일 기반이라 백엔드 무관).
- 소스 우선순위(furiosa): ① `furiosa_smi_py`(가능하면: `list_devices()` → `core_utilization()`/`memory_utilization()`/`power_consumption()`/`temperature()` — API 명은 설치된 패키지에서 확인) ② `furiosa-smi status --format json`(있으면) ③ `furiosa-smi status` 텍스트 파싱 ④ 파싱 실패 시 **raw 출력 라인을 그대로 `npu_raw.log` 에 저장하고 경고**(실기기 포맷은 사용자가 준비한 VM 에서 확인 후 파서 보강). vllm: `nvidia-smi --query-gpu=utilization.gpu,memory.used,memory.total,power.draw,temperature.gpu --format=csv,noheader,nounits`. llamacpp/mock: `/proc/stat` CPU 사용률 + RSS 로 같은 CSV 를 만들어 **코드 경로를 로컬에서 검증**(SIMULATED 표기).
- 산출: `npu_samples.csv`, `npu_summary.json/txt`(구간별 평균·피크 util, 메모리 피크, 샘플 수, 시작/끝), `npu_utilization.png`(matplotlib: 위 util%, 아래 mem, phase 구간 음영·라벨; matplotlib 없으면 설치 시도 → 실패 시 `npu_utilization.txt` ASCII 그래프로 대체하고 경고).
- 종료: run 이 끝나면 모니터에 SIGTERM, 남은 샘플 flush. 모니터가 죽어도 시험 자체는 계속(모니터 실패는 WARN).
- report.md/summary.json 에 "E. NPU 점유(참고)" 절 추가 — 판정 기준은 아님(A~D 만 판정), 시험원에게 "모델이 NPU 위에서 돌았다"를 보여주는 보조 증빙.

### 3-3. `bin/tc3 live`
- `tmux new-session -d -s tc3 'bin/tc3 run "$@"' \; split-window -h -l 45% 'watch -n1 -t "furiosa-smi status; echo; furiosa-smi ps"' \; attach`. 백엔드별 우측 명령은 `be_live_panel_cmd`. 창 크기 160×60 가정(캡처 스크립트와 맞춤). 종료 시 왼쪽 패널 결과가 지워지지 않도록 `remain-on-exit` 또는 run 끝에 `read -p "Enter 로 닫기"`.
- tmux 미설치 → 설치 시도(apt, 사전준비 항목에 추가) 실패 시 `run --inline-monitor` 로 자동 전환하고 안내.

### 3-4. `bin/tc3 result`

- **① 사전준비 (시험 전 완료, 시험 당일은 확인만)** — 표로: OS/커널, 드라이버·SDK 고정 버전, 모델 가중치·artifact(출처·커밋·크기), 키트(저장소·커밋), 설정(tc3.env 주요 값), 네트워크 불필요 선언. 당일 명령: `bin/tc3 preflight` → "문제 없음" 캡처 1장(`TC3_prep_preflight.png`).

- **③ 결과 저장 및 확인** — 명령: `bin/tc3 result` → `RESULT.md` cat 캡처, `bin/tc3 result --files` → 주요 로그 cat 캡처, `result --zip` 으로 제출 파일 생성. 증빙 디렉터리 목록 캡처.

**시험결과**: 판정 증빙 A~D + (참고) E NPU 점유 요약, 결론 문장(기존).

## 5. 제약·금지

- 기존 단계 명령(`env`…`report`)과 evidence 레이아웃·`status.tsv` 포맷은 **호환 유지**(절차서 v0.3, 캡처 도구, 테스트가 의존).
- 외부 서버(192.168.90.x, 210.114.95.x, 101.79.0.102)에는 사용자가 "VM 준비됐다, 접속해 봐라"고 명시하기 전에는 접속하지 않는다. 접속하더라도 **다른 프로세스·VM·NPU 작업을 중지/재시작하지 않는다**(`tc3 stop` 은 자기 서버만). 공용 테스트베드 원칙.
- 토큰·비밀번호는 화면/로그/캡처에 남기지 않는다(기존 hf-login 방식 유지).
- 파일은 LF. 커밋 메시지는 한국어 한 줄 요약 + 본문. 큰 바이너리(캡처 PNG, zip, 모델)는 커밋하지 않는다(.gitignore).
- `tc3.env.example` 의 버전 고정(조합 A 기본)은 유지하되, **사용자가 VM 에 설치한 실제 버전이 다르면 preflight 가 "기대≠실제"를 표로만 보여주고 FAIL 로 막지는 않도록 `TC3_STRICT_VERSIONS=0` 기본**(사전준비는 사용자 책임이므로). `=1` 이면 기존처럼 막음.

## 9. 절차서 작성용 인계 번들 (`handover/` — 개발 완료 후 반드시 생성)

절차서(hwpx TC3 절)는 다른 세션이 이 번들만 보고 작성한다. 캡처와 로그를 단계에 자동 대응시키므로 **형식을 지킬 것**.
`bin/tc3 handover` (또는 `tools/make_handover.sh`) 한 명령으로 아래를 `handover/tc3-handover-<YYYYMMDD-HHMM>.zip` 에 묶는다.

```
handover/
├── MANIFEST.json            {"kit_commit","generated","backend","vm":{"name","flavor","image","ip"},"versions":{"driver","furiosa-smi","furiosa-llm","artifact"},
│                             "timings":{"serve_ready_s","soak_total_s","soak_n"},"runs":{"reference":"evidence/<run>","user":"evidence/<run>|null"}}
├── evidence/<run>/          기준 run 전체 (stepNN_*.log, status.tsv, summary.json, RESULT.md, soak_result.csv,
│                             npu_samples.csv, npu_summary.txt, npu_utilization.png, prep_check.log/json, server.log)
├── captures/<ts>/*.png      단계별 터미널 캡처 (창 전체, 가로 ≥ 140열, 글자 크기 그대로 — 축소 금지)
├── captures/<ts>/index.json [{"file":"TC3_step05_model_size.png","phase":"P2","step":"05","id":"2-2",
│                              "command":"bin/tc3 model-size","title":"모델 파라미터 수 산출","log":"evidence/<run>/step05_model_params.log"}, ...]
├── horizon/*.png            Instance 상세·Flavor 상세 (사용자가 넣음 — 없으면 비워 두고 MANIFEST 에 "horizon":"pending")
├── docs/PROCEDURE_v2.md, README.md, VM_RUNBOOK.md
└── tc3.env.redacted         비밀값(HF_TOKEN 등) 제거본
```

- `captures/index.json` 의 `id` 는 절차서 항목 번호(1-1 … 1-6, 2-0 … 2-9, 3-1 … 3-3)와 같게. 한 단계에 캡처가 여러 장이면 같은 id 로 여러 항목.
- 캡처 파일명 규칙: `TC3_<phase>_<id>_<slug>.png` (예: `TC3_P2_2-2_model_size.png`). 창 제목에 단계명이 보이게.
- 캡처 안에 토큰·비밀번호·내부 IP 외 민감정보가 없을 것(192.168.90.x 는 허용).
- 기준 run 은 **실기기 VM 에서 SIMULATED 0건으로 끝난 run** 이어야 한다. 로컬(vm-sim) run 은 `runs.reference` 에 넣지 말고 `runs.sim` 로 따로.
- 사용자가 직접 돌린 run 이 있으면 `runs.user` 에 넣는다(절차서 작성 세션이 기준 run 과 자동 비교).
